# Микільсько-Слобідська.info

Громадський архів про захоплення 7,07 га берега Дніпра на Микільській Слобідці.
Це відтворення сайту, який із 2017 року працював на WordPress, у вигляді
**статичного сайту на Nuxt 4** — без бази даних, PHP і платного хостингу.

---

## Що всередині

| Розділ | Маршрут | Вміст |
|---|---|---|
| Хронологія (головна) | `/` | 6 ключових подій + вступ до архіву |
| Детальна історія злочину | `/crime-story-details/` | 40 подій, 2007–2021 |
| Злочин: Микільсько-Слобідська 7–9 | `/злочин-микільсько-слобідська-7-9/` | 14 подій, 2003–2021 |
| Сторінка події | `/timeline/<slug>/` | 51 сторінка |
| Порушені закони | `/laws-that-have-been-violated/` | 43 статті у 7 категоріях |
| Сторінка статті | `/violated_laws/<slug>/` | 44 сторінки (одна — копія зі старого WP) |
| Матеріали | `/materials/` | 6 аналітичних текстів |
| Роздрукуй та пошир | `/print-and-share/` | 6 плакатів у високій роздільності |
| Долучитися | `/долучитися/` | YouTube, Facebook, Viber |

Разом — **110 сторінок** і понад 250 файлів (зображення, скани, афіші) у `public/media`.

Усі адреси збережено такими, якими вони були на WordPress, тому зовнішні
посилання на старий сайт продовжать працювати.

## Команди

```bash
npm install
npm run dev        # локальна розробка -> http://localhost:3000
npm run generate   # статична збірка -> .output/public
npm run preview    # переглянути зібране
npm run verify     # звірити текст зібраного сайту з архівом WordPress
```

## Публікація

`npm run generate` створює теку `.output/public` — це звичайні HTML-файли.

### 1. Репозиторій на GitHub

Створіть **приватний** репозиторій (без README, .gitignore і ліцензії — вони вже є),
далі з теки проєкту:

```bash
git remote add origin git@github.com:<ваш-акаунт>/slobidka.git
git branch -M main
git push -u origin main
```

Перший push триватиме кілька хвилин: у репозиторії ~38 МБ медіа.

### 2. Cloudflare Pages

Workers & Pages → Create → Pages → **Connect to Git** → оберіть репозиторій.

| Параметр | Значення |
|---|---|
| Framework preset | Nuxt (або None) |
| Build command | `npm run generate` |
| Build output directory | `.output/public` |
| Environment variable | `NODE_VERSION` = `22` |

`.nvmrc` уже задає версію Node, але змінна `NODE_VERSION` надійніша — вона
не залежить від того, який build image увімкнено в проєкті.

Далі кожен push у `main` розгортається автоматично, а гілки й pull requests
отримують окремі preview-адреси.

### 3. Домен

У проєкті Pages: **Custom domains** → Set up a domain → `slobidka.info`.
Cloudflare попросить перевести домен на свої DNS-сервери (безкоштовно) або
додати CNAME у поточного реєстратора. Після цього старий хостинг можна
відключати — платити лишиться тільки за доменне ім’я.

### Що вже враховано

- `public/_headers` — кешування та заголовки безпеки
- `404.html` — Cloudflare підхоплює його автоматично
- жодного файлу понад 25 МіБ (обмеження Pages), усього 536 файлів з 20 000 дозволених
- кириличні адреси працюють як є

Збірку перевірено з чистого клону: `npm ci && npm run generate` дає ті самі
110 сторінок.

### PDF переведено у зображення

Усі 14 PDF (42 МБ) переведено у WebP, щоб матеріали відкривалися просто
в браузері, без завантаження файлів і сторонніх переглядачів. Разом — 15 МБ.

Роздільність підібрано за типом: афіші рендеряться у 300 dpi (якість друку),
скани документів — у 200 dpi, бо через зернистість вони у 300 dpi важать
більше за самі PDF. Багатосторінкові документи стали окремими зображеннями,
у тексті вони позначені переліком сторінок.

Оригінальні PDF — майстри для друку — лежать поза репозиторієм,
у `~/Archives/slobidka/print-originals/`. Перезапустити конвертацію:
`python3 scripts/convert-pdfs.py` (потрібні poppler і Pillow; шлях до
оригіналів задається змінною `ORIGINALS_DIR`).

## Як влаштований контент

Контент не редагується через адмінку — він лежить у JSON і збирається у HTML
на етапі збірки.

```
archive/                   архів оригінального WordPress
  wordpress-html/          117 збережених сторінок
  wordpress-json/          проміжний розбір, метадані з бази, мапа PDF
  map.tsv, urls.txt        відповідність файлів і адрес

scripts/
  prepare-content.mjs      archive/ -> app/data/*.json (іконки, чистка HTML, зв’язки)
  verify-content.mjs       перевірка, що жоден текст не загубився
  convert-pdfs.py          PDF -> WebP, оригінали в archive/print-originals
  postbuild.mjs            збирає справжній 404.html після генерації

app/data/                  дані сайту (їх і редагувати, якщо треба щось змінити)
  timelines.json           три стрічки подій
  events.json              51 сторінка події
  laws.json                44 статті + категорії
  pages.json               текстові сторінки
  site.json                назва, опис, соцмережі
  icons.json               набір SVG-іконок (Lucide)
```

Щоб змінити текст — правте `app/data/*.json` і запускайте `npm run generate`.
`npm run content` перезбирає дані з `archive/` і **перезапише** ручні правки.

## Що лежить поза репозиторієм

Великі резервні копії навмисно не в git, щоб не роздувати клонування:

| Що | Де |
|---|---|
| Дамп бази WordPress (3,1 МБ) | `~/DB_Backups/` |
| Оригінальні PDF, майстри для друку (67 МБ) | `~/Archives/slobidka/print-originals/` |

Сайт від них не залежить — вони потрібні лише як архів і для повторного друку.

## Дизайн

Власна тема замість `education-hub`. Мотив — досьє розслідування: сірий
супутниковий знімок із червоним контуром захопленої ділянки задає палітру,
стрічка часу працює як хребет сайту.

- Шрифти: Unbounded (заголовки), Manrope (інтерфейс), Inter (текст) —
  самохостяться через `@nuxt/fonts`, з кириличними підмножинами
- Світла й темна теми, вибір зберігається в браузері
- Іконки — Lucide, вбудовані у збірку (замість FontAwesome зі старої теми)
- Скани документів відкриваються в лайтбоксі в оригінальному розмірі
- Сторінки законів і матеріалів придатні для друку

## Що дала база даних

Крім сторінок, знято повний дамп БД. Він містить `wp_users` із хешами паролів,
тому лежить **поза репозиторієм** — у `~/DB_Backups/`.

Звірка з ним показала те, чого не було видно в HTML:

- **6 відео з YouTube** були прив’язані до подій у полі `ctl_video`, але плагін
  не виводив їх на сторінках — тобто на старому сайті вони фактично не
  показувалися. Тепер вони на своїх місцях; обкладинки лежать локально, плеєр
  вантажиться лише після кліку.
- **Точні дати всіх 51 події** (`ctl_story_date`) — тепер у розмітці як `<time datetime>`
- **19 файлів медіатеки**, на які ніщо не посилалося через `src` (серед них
  іконки категорій законів, що були у CSS-фоні) — довантажені в архів

Чого в базі не виявилося: коментарів (0), значущих чернеток, втраченого тексту
в 176 ревізіях. Усі 35 «мініатюр» подій уже були в архіві.

Сторінка «Порушені закони» рендерилася PHP-шаблоном теми
(`template-broken-laws.php`) і мала порожній вміст у базі — цей файл лишається
тільки на диску хостингу. Тут сторінка зібрана з 44 структурованих записів,
тому шаблон не потрібен.

## Що виправлено проти оригіналу

- посилання на Viber-спільноту на сторінці «Долучитися» було збережено з
  помилкою і не відкривалося
- «Стаття 91. Смуги відведення» була опублікована двічі — у переліку лишилась
  одна, друга сторінка збережена задля старих посилань
- чотири події хронології не мали власних посилань і були недосяжні
- розміри PDF показуються реальні, а не з підписів, які подекуди застаріли
- 6 відео, прив’язаних до подій, взагалі не виводилися на старому сайті
